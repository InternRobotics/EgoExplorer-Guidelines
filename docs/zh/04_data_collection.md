# 4. 如何采集数据

[返回目录](../index.md) · [English](../en/04_data_collection.md)

具体启动命令见第 3 章（待补充）；本章讲一次采集日的流程和规范。

## 4.1 一次采集日的流程

```text
穿戴（第 1 章） → 主机自检（第 2.6 节） → 录 01–17 标定（第 5 章） → 按任务清单逐条录制 → 上传 → 填写采集记录
```

1. **穿戴并自检。**
2. **先录标定。** 每次穿戴都要录（同一次穿戴可以录 2–3 条备用）。标定和任务数据放在同一天的采集目录下，但标定 session 要能从名字区分出来。
3. **按任务清单录制。** 采集程序用 `--task-setting <json>` 读任务流程，内容是一个非空的任务名数组，例如：
   ```json
   ["物料称量", "萃取", "开反应", "旋蒸", "烘箱取料", "过柱"]
   ```
   页面上选好当前任务后开始录制，任务名会写进 session 名和 `session.json` 的 `task_name`。
4. **录制控制**（网页按钮和终端键盘等价）：

   | 键 | 作用 |
   |---|---|
   | `r` | 开始：先倒计时（默认 3 秒，可在页面临时改），结束时有提示音 |
   | `d` | 倒计时中按：取消；录制中按：**终止并丢弃**，不落盘 |
   | `e` | 结束并保存：写 mp4、手套 npz、tracker npz、视频时间戳、session.json，并追加当天录制日志 |
   | `q` | 退出 |

5. **上传**：会话保存后可手动触发 rclone 上传（`copy --ignore-existing`，重复点击安全）；本地数据目录超过容量上限（默认 50 GB）时自动 `move --checksum`，只清理已校验上传成功的文件。
6. **采集记录**：程序会在数据目录同级写 `recording_log_<日期>.csv`（每条 session 的起止时间、时长、各流帧数），用来统计每日时长。

## 4.2 命名与目录

- session 名：`session_<YYYYMMDD>_<HHMMSS>_<任务名>`，例如 `session_20260901_154755_物料称量`。
- "恢复"类录制（应对中断、失败后的纠正）在任务名后加 `_恢复`，例如 `session_20260901_164121_过柱_恢复`。这类录制是刻意采集的，保留下来覆盖人如何纠错。
- 每条 session 一个目录，里面五个文件（格式见第 6 章）。
- 处理时按 batch 组织：同一位受试者、同一次穿戴的录制放进同一个目录（第 7.3 节）。

## 4.3 录制规范

- **每段开头站定 2–3 秒**再开始动作，结尾也停 1–2 秒。投影和左右检查都用起始站姿做判据。
- **全程不碰 tracker 和绑带。** 一旦碰歪，在采集记录里注明，必要时重录标定。
- **手部 tracker 必须在录。** 历史上部分 `_恢复` 录制只有视频有效、手腕 tracker 根本没动，这类 session 无法重建身体。
- **单段时长**：实验室任务通常 2–7 分钟。太长的录制可以拆成多段。
- **不同受试者的数据要能区分。** 管线按受试者选标定 profile（第 5.6 节）；如果同一套设备换人，务必在采集记录里写清楚，否则只能事后从头部高度推断。

## 4.4 采集后检查

- 打开 `session.json`：`video.queue_dropped_frames`、`read_failures`、`writer_failures` 应为 0；`tracker.dropped_frames` 应为 0；`overlap_s` 应接近录制时长。
- 手套 `meta` 里每路的 `frames` 和 `duration_s` 应与视频时长一致。
- 有条件的话在采集机上用 viewer 快速回放一条，确认五个 tracker 和手套都在动。
